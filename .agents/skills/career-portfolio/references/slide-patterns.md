# Slide Patterns

- `cover`: identity, concise promise, one supporting detail
- `career-map`: chronology or repeated problem-solving pattern
- `project-overview`: context, scope, responsibility, key result
- `problem`: user pain, prior state, constraints, stakes
- `architecture`: system boundary, components, flows, ownership
- `decision`: options, tradeoff, chosen approach, consequence
- `workflow`: sequence, state transitions, operations
- `evidence`: screenshot, metric, observable behavior, provenance
- `results`: outcomes with baseline and scope
- `role`: personal contribution versus team boundary
- `closing`: synthesis and contact

Use `split`, `lead`, or `evidence` layout. A slide type describes communication intent; a layout describes composition.
