두 방향의 차이 — 시작하는 방법이 다르다

무엇을 하는가

기능은 같지만 통화가 시작되는 방식이 다르고, 그 차이에서 아웃바운드 고유의 사건이 나옵니다.

어떻게 만들었나

아웃바운드
  • 시작 · voxBridge가 SIP 참가자를 만들고 워커는 기다림
  • 게이트 · FakeAgent → active(60초) → AMD → SingleAgent(human/uncertain만)
  • 지식 · FAQ 벌크 프롬프트 주입(get_faqs)
  • 목적 · 발신 시점에 이미 정해져 있음
인바운드
  • 시작 · SIP 수신 후 참가자 admission
  • 게이트 · 유효한 metadata와 참가자 확인
  • 지식 · Call Context 주입 + no-knowledge fallback
  • 목적 · 통화 중에 알아내야 함

뭐가 깨졌나

  • 1 · AMD race condition — 판별 중 시작된 발화가 전환 후 완료돼 인사말 대신 LLM 응답이 나가던 문제. FakeAgent·GreetingDtmfTask에 StopResponse를 강제해 해결
  • 2 · 늦은 STT — 통화 종료 후 발화처럼 보이던 문제. 분석에서 PARTICIPANT_DISCONNECTED를 끝으로 이동 후 분류
  • 3 · DTMF provenance 누수 — 일회성 키패드 선택이 자율 도구 호출로 새던 문제. get_my_appointment_list가 시작 시 from_dtmf_selection을 제거
동시성 상한 · compute_load()가 활성 잡 5개를 기준으로 계산해 연결 5통 + 셋업 1건까지 허용하고 7번째를 막습니다.
