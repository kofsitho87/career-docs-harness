# Repository Documentation Design

**작성일:** 2026-03-07
**대상:** 이 저장소를 이해하거나 유지보수할 본인 및 향후 에이전트 세션
**문서 목적:** 이 저장소가 이력서·포트폴리오 제작용 agent harness라는 점을 빠르게 이해할 수 있도록, 소개 문서와 운영 문서를 분리한 문서 구조를 정의한다.

## 문제 정의

현재 저장소에는 최종 산출물, 원본 경력 문서, 작성 가이드, 설계 문서, 로컬 스킬, 런타임 상태가 함께 존재한다.

- 처음 보는 사람이 어떤 파일이 결과물이고 어떤 파일이 작업용 문서인지 빠르게 구분하기 어렵다.
- 루트에 프로젝트 소개 문서가 없어 저장소의 목적과 읽는 순서를 한눈에 파악하기 어렵다.
- 현재 워크플로우가 암묵적으로 존재하여, 다음 세션에서 같은 흐름을 재사용하기 어렵다.

## 목표

- 루트 `README.md`에서 저장소의 목적과 핵심 결과물을 빠르게 설명한다.
- `docs/workflow.md`에서 문서 생산 흐름과 파일 역할을 명확히 정리한다.
- 이 저장소를 "문서 모음"이 아니라 "resume/portfolio production harness"로 이해할 수 있게 한다.
- 다음 에이전트 세션이 참고할 수 있는 실질적인 운영 기준을 남긴다.

## 비목표

- 이력서/포트폴리오 본문 내용을 다시 작성하지 않는다.
- 디렉터리 구조를 이번 단계에서 재편하지 않는다.
- `.omx`, `.omc`, `.agents/skills` 내부 동작을 모두 상세 문서화하지 않는다.

## 제안 구조

### 1. `README.md`

빠른 입구 역할의 문서다.

- 저장소 한 줄 설명
- 무엇을 만드는 저장소인지
- 현재 핵심 산출물 링크
- 주요 디렉터리 설명
- 처음 읽는 순서

### 2. `docs/workflow.md`

운영 문서 역할의 문서다.

- source-of-truth 문서
- 가이드/설계 문서
- 최종 산출물
- 에이전트 스킬 및 런타임 상태
- 작업 흐름: 원본 정리 -> 가이드/설계 -> 산출물 작성 -> 자산 생성
- 현재 알려진 갭과 향후 정리 포인트

## 설계 원칙

1. `README.md`는 짧고 스캔 가능해야 한다.
2. `docs/workflow.md`는 실행 가능한 설명이어야 한다.
3. 파일 역할을 결과물/과정 문서/자동화 상태로 구분한다.
4. 현재 저장소 상태를 과장 없이 반영하고, 없는 자동화를 있는 것처럼 쓰지 않는다.

## 기대 결과

- 새로운 세션이 시작되어도 저장소 목적과 작업 순서를 빠르게 재구성할 수 있다.
- 결과물과 작업용 문서를 혼동하지 않게 된다.
- 이후 구조 정리 또는 README 확장의 기반 문서가 생긴다.
