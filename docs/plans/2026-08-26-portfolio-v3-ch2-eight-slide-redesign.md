## 현재 방향

- CH 02는 실제 운영 화면의 가독성, 운영 개선 설명과 28개 규칙 기반 통화 분류를 위해 5장에서 8장으로 확장한다.
- 챕터 이름은 기술적인 `통화 관측과 평가` 대신 기능을 바로 설명하는 `인/아웃바운드 통화 분석 및 평가`를 사용한다.
- 챕터의 핵심은 **불완전한 통화 기록을 신뢰할 수 있는 결과로 재구성하고, 같은 기준으로 다시 계산할 수 있는 운영 데이터로 만드는 것**이다.
- 챕터의 흐름은 `전체 분석 시스템 → 기록 복원 → 28개 활동 분류 → 업무/통화 결과 계산 → 근거 기반 AI 평가 → 현황 확인 → 문제 진단 → 재계산과 운영 개선`으로 전개한다.
- CH 01의 마지막 장과 역할을 분리한다. CH 01은 운영 결과를 보여주고, CH 02는 그 결과가 어떻게 만들어지고 개선에 사용되는지를 설명한다.
- 첫 장은 인·아웃바운드 통화 분석 시스템의 범위와 전체 흐름을 직접 설명한다. 10단계 내부 파이프라인을 소개 장의 중심에 두지 않는다.
- Kafka Consumer는 handler가 정상 종료된 뒤에만 입력 offset을 commit하고, 통화 서비스와 별도 배포·장애 경계를 가진다. 이 기술 사실은 “분석이 실패해도 실제 전화는 계속된다”는 사용자 언어로 표현한다.
- 상담원 연결 이후의 누락 구간은 녹음 준비를 재확인하고, 연결 이후 구간만 복원해 기존 대화 순서에 삽입한다. 녹음 기준 시각은 `recording_started_at`을 우선 사용한다.
- 확실한 업무 결과는 저장된 이벤트의 배열 순서에 따라 `이벤트 → 업무별 시도 → 통화 전체 결과`로 계산한다. LLM은 이 결과를 바꿀 수 없다.
- 한 통화 안의 여러 업무 시도와 통화 전체 대표 결과를 분리한다. 대표 결과는 정확히 하나만 남겨 중복 KPI를 막는다.
- `InboundConversationMetadata`의 28개 boolean 분류는 통화당 하나가 아니라 여러 항목이 동시에 감지되는 상세 활동층으로 설명하고, Analytics v2의 업무별 시도·대표 결과와 구분한다.
- LLM은 임상·긴급도·환자 경험·미지원 요청·응답 품질처럼 해석이 필요한 영역만 평가한다. 환자 의도는 환자 발화만 근거로 사용할 수 있다.
- LLM 평가 결과는 별도 버전으로 저장한다. 민감한 임상·QA 소견은 downstream Kafka에서 제외하고, Langfuse에는 transcript·임상 소견·평가 근거 없이 집계 점수만 전송한다.
- 규칙 변경은 LLM 재호출 없이 과거 통화를 버전 기반으로 다시 계산할 수 있다. AI 평가의 신뢰도 기준도 저장된 원본을 유지한 채 리포트 시점에 조정할 수 있다.
- `결정론적 분석`, `의미 QA`, `귀인`, `rollup`, `events`, `attempts` 같은 용어를 헤드라인과 핵심 문장에서 피한다.
- 기술 용어가 꼭 필요하면 쉬운 설명을 먼저 쓰고, 구현 근거로만 작게 병기한다.
- 남은 슬라이드도 아이콘·타임라인·상태 흐름·실제 화면 중 메시지에 맞는 시각 요소를 최소 하나 사용한다.
- 1920×1080 기준으로 카드 핵심 문구와 보조 문구가 작게 보이지 않도록, CH 02의 시각 요소는 기존 공통 컴포넌트보다 한 단계 큰 글자와 아이콘을 기본으로 사용한다.
- 통화 한 건의 결과와 업무별 시도 결과를 섞지 않는다.
- 분석 범위는 인바운드가 중심이다. 아웃바운드와 분석 파이프라인이 다르다는 사실은 범위 설명으로만 남기고, 두 시스템의 성숙도 비교를 챕터의 중심 서사로 사용하지 않는다.
- 1장은 인·아웃바운드 공통 목적과 분석 시스템 경계를 다루고, 2~8장은 규칙 기반 28개 활동 분류, 결과 계산·근거 기반 평가·운영 화면·버전 재처리가 갖춰진 인바운드 분석을 중심 사례로 사용한다.
- LLM 평가는 운영 결과를 임의로 바꾸는 판정기가 아니라, 근거가 있는 품질 신호를 추가하는 역할로 표현한다.
- 환자 transcript·임상 정보·식별 정보는 화면과 외부 관측 도구에 노출하지 않는 개인정보 경계를 유지한다.
- 3장은 28개 규칙 기반 분류의 네 그룹과 실제 비식별 분류 카드 화면을 보여준다. 6장은 실제 운영 현황, 7장은 실제 통화 분석 화면을 한 장씩 크게 보여주고, 8장은 두 화면이 규칙 개선과 버전 재분석으로 이어지는 운영 루프를 설명한다.
- 3·6·7장의 스크린샷은 클릭하면 전체 화면 모달로 확대되며 Escape·배경 클릭·닫기 버튼으로 닫을 수 있다.
