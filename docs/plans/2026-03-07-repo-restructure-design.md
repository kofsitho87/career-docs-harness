# Repository Restructure Design

**작성일:** 2026-03-07
**대상:** 이 저장소를 유지보수할 본인 및 향후 에이전트 세션
**문서 목적:** 이력서·포트폴리오 제작용 harness라는 저장소 성격이 파일 구조에서 더 명확하게 드러나도록 디렉터리와 파일명을 정리한다.

## 문제 정의

현재 저장소는 핵심 문서와 최종 산출물이 섞여 있어 각 파일의 역할이 즉시 드러나지 않는다.

- 최종 이력서가 루트에 있어 결과물과 운영 문서의 경계가 약하다.
- 포트폴리오는 `projects/`에 있지만 이력서는 별도 위치에 있어 결과물 계층이 일관되지 않다.
- 원본 이력서와 가이드 문서도 `docs/` 아래에서 역할별 분리가 충분하지 않다.
- 이미지 자산이 루트에 있어 문서 산출물과 보조 자산의 구분이 흐려진다.

## 목표

- 기능 중심 네이밍으로 저장소 구조를 정리한다.
- 최종 산출물, 사실 기준 문서, 작성 가이드, 자산을 역할별 디렉터리로 구분한다.
- 기존 문서 흐름인 `source -> guide/plan -> final output -> assets`를 파일 구조에서도 읽을 수 있게 한다.
- 기존 문서 내용은 유지하고, 참조 경로만 정확히 갱신한다.

## 비목표

- 이력서나 포트폴리오 본문을 다시 작성하지 않는다.
- `docs/plans/` 구조 자체는 바꾸지 않는다.
- `.claude/skills/` 같은 로컬 스킬 구조는 이번 단계에서 건드리지 않는다.

## 제안 구조

### 최종 산출물

- `resume/product-engineer.md`
- `portfolio/outbound-voice-agent.md`

### 사실 기준 문서와 가이드

- `docs/source/origin-resume.md`
- `docs/guides/resume-guide.md`

### 자산

- `assets/heewung-song-infographic.png`

### 유지 항목

- `README.md`
- `docs/workflow.md`
- `docs/plans/`
- `.claude/skills/`

## 설계 원칙

1. 결과물은 루트가 아니라 역할별 디렉터리에 둔다.
2. `docs/`는 설명, 가이드, 계획 문서 중심으로 유지한다.
3. 이미지 같은 보조 자산은 `assets/`로 모은다.
4. 경로 변경 시 현재 문서에서 깨지는 참조를 함께 수정한다.

## 기대 결과

- 저장소를 처음 열었을 때 결과물과 작업 문서의 역할이 더 분명해진다.
- 이후 포트폴리오 프로젝트가 늘어나도 `resume/`, `portfolio/`, `assets/`, `docs/` 구조 안에서 자연스럽게 확장할 수 있다.
- README와 workflow에 적힌 설명이 실제 파일 구조와 더 잘 일치하게 된다.
