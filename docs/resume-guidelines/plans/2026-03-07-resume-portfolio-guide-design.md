# 개발자 이력서·포트폴리오 가이드 디자인 문서

**작성일:** 2026-03-07
**대상:** 국내 채용용 한국어 이력서를 준비하는 개발자
**문서 목적:** 좋은 개발자 이력서와 포트폴리오의 공통 원칙, 권장 구조, 작성 규칙, 체크리스트를 한 문서로 정리해 실제 작성에 바로 적용할 수 있게 한다.

## 문제 정의

개발자 이력서와 포트폴리오는 흔히 다음 문제를 가진다.

- 사용 기술만 길게 나열하고 실제 기여와 결과가 잘 보이지 않는다.
- 경력 요약, 프로젝트 설명, 포트폴리오 링크가 서로 중복되거나 역할이 불명확하다.
- 채용 담당자가 짧은 시간 안에 핵심 역량과 최근 임팩트를 파악하기 어렵다.
- 본문은 장황한데 정작 신뢰를 주는 수치, 맥락, 역할 구분은 부족하다.

이번 문서는 이 문제를 해결하기 위해 "읽는 사람 기준"과 "작성하는 사람 기준"을 함께 제공해야 한다.

## 목표

- 좋은 개발자 이력서와 포트폴리오의 공통 원칙을 설명한다.
- 이력서 각 섹션의 권장 구조와 작성 규칙을 제시한다.
- 포트폴리오를 프로젝트 목록이 아니라 검증 가능한 대표 사례 묶음으로 설계하는 법을 설명한다.
- 이력서와 포트폴리오의 역할 분담을 명확히 한다.
- 제출 전 바로 사용할 수 있는 체크리스트와 템플릿을 제공한다.

## 비목표

- 특정 회사나 직무 하나에만 맞춘 맞춤형 자기소개서 작성법은 다루지 않는다.
- 디자인 중심 포트폴리오나 비개발 직군 전용 포트폴리오 구조는 다루지 않는다.
- 화려한 웹 포트폴리오 구현 방법 자체는 다루지 않는다.

## 핵심 원칙

1. 이력서는 판단을 빠르게 돕는 요약 문서여야 한다.
2. 포트폴리오는 이력서의 주장을 검증하는 증거 문서여야 한다.
3. 좋은 문장은 기술 나열보다 문제, 역할, 행동, 결과를 우선한다.
4. 최근성과 관련성이 오래된 경험보다 우선한다.
5. 과장된 형용사보다 사실, 수치, 범위, 맥락이 신뢰를 만든다.

## 문서 구조

1. 좋은 이력서와 포트폴리오의 공통 특징
2. 좋은 개발자 이력서의 구조
3. 섹션별 작성 가이드
4. 좋은 포트폴리오의 구조
5. 이력서와 포트폴리오의 역할 분담
6. 자주 약해지는 포인트와 개선법
7. 제출 전 체크리스트
8. 부록 템플릿

## 문체 및 스타일 기준

- 국내 채용용 한국어 문서 기준으로 쓴다.
- 과장된 자기평가, 추상적 성장 서사는 줄이고 판단 가능한 표현을 사용한다.
- 실무자가 바로 수정에 반영할 수 있게 문장 공식과 예시를 포함한다.
- 짧은 문단과 명확한 불릿 위주로 구성한다.
