# 채용공고 검색 프로토콜

## 1. 목적

이 문서는 에이전트가 사용자의 원하는 포지션, 기술 스택, 경력 조건을 입력받아 적합한 채용공고를 일관된 방식으로 찾고 평가하기 위한 내부 운영 프로토콜이다.

대상 사이트:

- `https://www.wanted.co.kr`
- `https://www.jobplanet.co.kr`
- `https://jumpit.saramin.co.kr`

핵심 목표:

- 사용자의 희망 포지션과 실제 경력 사이의 적합도를 빠르게 판단한다.
- 사이트별 검색 방식 차이와 차단 이슈를 감안해 재현 가능한 절차로 공고를 수집한다.
- 최종 결과를 단순 나열이 아니라 우선순위와 근거가 있는 추천 목록으로 정리한다.

## 2. 입력값 정의

검색을 시작하기 전에 아래 입력값을 먼저 구조화한다.

### 2.1 필수 입력값

- 목표 포지션명
- 주요 기술 스택
- 최소 경력 / 선호 경력 범위
- 선호 지역
- 제외 조건

예시:

```text
목표 포지션: AI Product Engineer, AI Backend Engineer
주요 기술: Python, FastAPI, TypeScript, Next.js, LLM, RAG, AWS
경력: 7년 이상
지역: 서울, 경기
제외 조건: 순수 모델 리서치 포지션, C++ 중심 포지션
```

### 2.2 있으면 좋은 입력값

- 도메인 선호: 헬스케어, B2B SaaS, 교육, 커머스 등
- 근무 형태 선호: 정규직, 하이브리드, 원격
- 우선순위: 연봉, 성장성, 기술 적합도, 제품 오너십, 회사 규모
- 회피 조건: 잦은 야근, 신입 중심 조직, 특정 기술 강제

## 3. 검색 전 해석 규칙

사용자 입력을 그대로 검색어로 넣지 말고 아래 3개 층위로 재구성한다.

### 3.1 역할 키워드

- 원문 포지션명
- 유사 포지션명
- 한국어 / 영어 변형

예시:

- `AI 엔지니어`
- `AI Agent Engineer`
- `LLM Engineer`
- `AI Backend Engineer`
- `Backend Engineer`
- `Product Engineer`

### 3.2 기술 키워드

- 언어: `Python`, `TypeScript`, `Node.js`
- 프레임워크: `FastAPI`, `Next.js`, `NestJS`
- 분야: `LLM`, `RAG`, `AI Agent`, `Voice AI`
- 인프라: `AWS`, `Docker`, `Kubernetes`

### 3.3 배제 키워드

사용자 스펙과 크게 어긋나는 포지션은 초기에 제외한다.

예시:

- `신입`
- `연구원`
- `C++`
- `임베디드`
- `컴파일러`
- `머신비전 전용`

단, 완전히 제외하지 말고 공고 제목과 주요업무를 1회 확인한 뒤 최종 배제한다.

## 4. 사이트별 검색 절차

모든 검색은 기본적으로 `agent-browser`를 사용한다. 각 사이트는 같은 방식으로 보지 않는다.

### 4.1 Jumpit

가장 구조화가 잘 되어 있으므로 1차 탐색에 우선 사용한다.

절차:

1. 메인 진입 후 검색창에 역할 키워드를 넣는다.
2. 결과가 너무 넓으면 기술 키워드로 2차 검색한다.
3. `관련도순`, `최신순`, `인기순`을 순서대로 확인한다.
4. 상위 결과에서 제목, 기술 스택, 경력 범위, 지역을 먼저 훑는다.
5. 적합 후보만 상세 페이지를 연다.

우선 확인 항목:

- 제목에 `AI`, `LLM`, `Backend`, `Agent`, `FastAPI`가 포함되는지
- 기술 스택에 핵심 기술 2개 이상이 겹치는지
- 경력 범위가 맞는지
- 주요업무가 제품 개발인지, 연구 전용인지

### 4.2 Wanted

직접 접근이 차단될 수 있으므로 공고 검색보다 공고 상세 접근 가능 여부를 먼저 판단한다.

절차:

1. 브라우저 접근 가능 여부를 확인한다.
2. 차단이 없으면 역할 키워드 중심으로 검색한다.
3. 차단이 있으면 공개 검색 인덱스나 외부 검색 결과에서 공고 ID를 확보한 뒤 상세 접근을 시도한다.
4. 상세 페이지가 열리면 주요업무, 자격요건, 우대사항만 우선 추출한다.

주의:

- CloudFront 차단이 걸리면 해당 세션에서 반복 시도하지 않는다.
- 접근 불가 사실을 기록하고 다른 사이트 결과 비중을 높인다.
- 상세 검증이 안 된 공고는 `보조 후보`로 분리한다.

### 4.3 JobPlanet

Cloudflare 차단 가능성이 높으므로 직접 탐색보다 접근 가능 여부를 먼저 본다.

절차:

1. 메인 접근 시 차단 여부를 확인한다.
2. 차단이 없으면 역할 키워드로 검색하고 상세 페이지를 연다.
3. 차단이 있으면 공개 검색 스니펫 수준에서 제목, 기술 키워드, 회사명만 수집한다.
4. 상세 페이지 검증이 되지 않으면 `미검증 후보`로 표시한다.

주의:

- 직접 접근이 막힌 상태에서 억지로 반복 시도하지 않는다.
- 스니펫 기반 결과는 반드시 `공개 인덱스 기준`이라고 명시한다.

## 5. 공고 선별 기준

각 공고는 아래 5개 항목으로 본다.

### 5.1 역할 적합도

- 사용자 목표 포지션과 제목이 직접 일치하는가
- 유사 포지션으로 해석 가능한가

### 5.2 기술 적합도

- 핵심 기술 스택이 2개 이상 겹치는가
- 핵심 분야 키워드가 겹치는가
- 현재 강점을 살릴 수 있는가

### 5.3 경력 적합도

- 최소 경력이 맞는가
- 지나치게 주니어 또는 지나치게 특수한 시니어 포지션은 아닌가

### 5.4 문제 영역 적합도

- 제품 개발 / 운영형 포지션인가
- 연구 전용 포지션인가
- 사용자 도메인 경험과 연결 가능한가

### 5.5 실행 가능성

- 실제 지원 가능한 지역 / 근무 형태인가
- 상세 요건상 명백한 결격 요소가 없는가

## 6. 적합도 점수화 규칙

점수는 내부 비교용이며 절대값이 아니다.

- 역할 적합도: 0~3점
- 기술 적합도: 0~4점
- 경력 적합도: 0~2점
- 도메인 / 문제 영역 적합도: 0~2점
- 실행 가능성: 0~1점

총점:

- `10~12점`: 최우선 후보
- `7~9점`: 지원 권장
- `4~6점`: 보조 후보
- `0~3점`: 제외

## 7. 배제 규칙

아래 중 2개 이상이면 제외 후보로 본다.

- 핵심 기술이 거의 겹치지 않음
- 경력 조건이 명확히 불일치함
- 연구 전용 포지션이라 제품 경험을 살리기 어려움
- 지역 / 근무 조건이 명확히 불가능함
- 공고 상세를 확인했을 때 역할이 완전히 다름

## 8. 예외 처리

### 8.1 사이트 차단

- `Wanted`, `JobPlanet`에서 차단이 발생하면 원인과 시점을 기록한다.
- 같은 방식으로 2회 이상 반복 시도하지 않는다.
- `Jumpit` 비중을 높이고, 나머지 사이트는 보조 수집으로 전환한다.

### 8.2 검색 결과 부족

- 역할 키워드를 넓힌다.
- 기술 키워드 중심 검색으로 전환한다.
- 너무 좁은 도메인 키워드는 제거한다.

예시:

- `Voice AI Engineer` 결과가 부족하면 `AI Engineer`, `LLM Engineer`, `Backend Engineer`로 확장

### 8.3 검색 결과 과다

- 핵심 기술 1개를 추가한다.
- 경력 필터를 우선 적용한다.
- 제목보다 주요업무와 자격요건 중심으로 좁힌다.

### 8.4 공고 정보가 불완전함

- 상세 페이지 접근 실패 시 `미검증` 상태로 둔다.
- 제목과 스니펫만으로 강한 추천을 하지 않는다.

## 9. 최종 결과 정리 형식

최종 응답은 아래 순서를 따른다.

### 9.1 먼저 정리할 것

- 어떤 기준으로 찾았는지
- 어느 사이트까지 직접 검증했는지
- 차단 또는 미검증 상태가 있는지

### 9.2 추천 목록 형식

각 공고마다 아래 항목을 정리한다.

- 사이트
- 회사명
- 공고명
- 링크
- 적합한 이유 2~3개
- 주의할 점 1~2개
- 우선순위

예시:

```text
1. Jumpit / 회사명 / 공고명
링크: ...
적합 이유:
- Python, FastAPI, AWS 운영 경험과 직접 연결됨
- LLM 서비스 아키텍처 설계 경험을 살릴 수 있음
주의:
- Node.js 비중이 높아 관련 경험 표현 보강 필요
```

### 9.3 마지막에 제공할 것

- 상위 3개 우선순위
- 공고별 이력서 보정 포인트
- 필요 시 추가 검색 방향

## 10. 응답 작성 원칙

- 공고를 단순 수집하지 말고 추천 근거를 반드시 붙인다.
- 사용자 이력서와 연결되는 문장으로 설명한다.
- 검증 수준을 구분한다.
  - `직접 상세 확인`
  - `검색 결과 수준 확인`
  - `공개 인덱스 기반 추정`
- 차단된 사이트 결과는 과장하지 않는다.
- 최신성이 중요한 정보이므로 검색 날짜를 명시한다.

## 11. 실행 체크리스트

- [ ] 사용자 목표 포지션과 스펙을 구조화했다.
- [ ] 역할 키워드, 기술 키워드, 배제 키워드를 만들었다.
- [ ] Jumpit에서 1차 탐색을 수행했다.
- [ ] Wanted 접근 가능 여부를 확인했다.
- [ ] JobPlanet 접근 가능 여부를 확인했다.
- [ ] 공고별 적합도와 배제 사유를 기록했다.
- [ ] 최종 추천 목록을 우선순위와 함께 정리했다.
- [ ] 차단 / 미검증 상태를 응답에 명시했다.
